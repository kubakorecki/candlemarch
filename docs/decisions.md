# Decisions

Short log of implementation choices where the spec or `CLAUDE.md` left room. One line each: date, decision, why. Newest at the bottom.

- 2026-09-23 — Workspace packages are consumed as TypeScript source (`exports` → `src/index.ts`), with no build step between them. Why: Vite and Vitest compile TS directly, so one less thing to keep in sync.
- 2026-09-23 — Import boundaries are enforced in four layers: declared pnpm dependencies (strict `node_modules`); no DOM lib in `content`/`sim` tsconfigs; Biome `noRestrictedImports`/`noRestrictedGlobals` overrides; `tooling/boundaries.test.ts` (manifest check plus a grep for `Math.random`/`Date.now`/`performance.now` in sim). Why: each layer is cheap, and together they catch both imports and hidden inputs.
- 2026-09-23 — The client typechecks the worker with a separate `tsconfig.worker.json` (`WebWorker` lib). Why: the DOM and WebWorker libs conflict in one program.
- 2026-09-23 — Added `pnpm format` (`biome check --write .`). Why: to apply Biome fixes; `pnpm lint` stays read-only.
- 2026-09-23 — `step(state, commands, content)` takes content as an argument, as in CLAUDE.md; the spec's `step(state, commands)` is older shorthand. Why: CLAUDE.md wins on engineering rules.
- 2026-09-23 — Tool versions at scaffold: TypeScript 7.0, Vitest 5.0, Biome 2.5, Vite 8.3, PixiJS 8.21, React 19.3, pnpm 11, Node ≥ 22.12. Why: latest stable versions at project start.
- 2026-09-23 — Trees are a `mapObjects` entry with generic fields (`resource`, `amount`, `gatherTicks`, `yieldPerGather`) instead of tree-specific ones. Why: the same shape fits later rocks and clay, and it costs nothing now.
- 2026-09-23 — Villager roles (`woodcutter`, `carrier`) are content, holding walk speed, carry capacity and idle retry. Walk speed is in milli-tiles per tick, so it stays an integer. Why: keeps every tuning number in content, as integers.
- 2026-09-23 — Buildings have a footprint (`size`) and a `door` tile just outside it that villagers walk to. Woodcutter's hut is 2×2; hut is 1×1. Why: a simple, explicit access point; footprints can block walking without villagers needing to enter tiles.
- 2026-09-23 — Milestone-0 numbers: tree 3 logs, 40 ticks per chop; walk 1.5 tiles/s; woodcutter's hut buffer 4 logs; hut costs 10 logs + 200 build ticks. Why: a hut completes in about 2 minutes at 1×, which is watchable at 3×.
- 2026-09-23 — State is ECS-lite: `state.components.<name>` stores are plain `Record<EntityId, T>`; an entity is the set of components sharing an ID. `idsOf()` returns IDs sorted ascending for any order-dependent loop. Why: JSON-safe, stable iteration, and an entity can change role (a site becomes a building and keeps its ID).
- 2026-09-23 — `step()` doesn't mutate its input: it deep-copies via a JSON round trip, then systems mutate the copy. Why: easy to test and to keep old states; the round trip also guards JSON-safety. Revisit if profiling on big maps shows the copy matters.
- 2026-09-23 — Trees and building/site footprints block walking; a villager's start tile never does. New sites don't reroute villagers already walking. Why: the simplest rules that make paths look sensible.
- 2026-09-23 — A* uses octile costs (1000 orthogonal, 1414 diagonal), doesn't cut corners past blocked tiles, and breaks ties by f, then h, then tile index. Why: deterministic paths that don't clip through tree trunks.
- 2026-09-23 — Placement: every footprint tile must be buildable and free of trees, footprints and doors; the door tile must be walkable and free. `canPlaceBuilding` is exported so the client preview uses the same rule. Why: keeps every door reachable and keeps game logic in sim.
- 2026-09-23 — Invalid commands are ignored silently. Why: deterministic, and the UI already prevents the common cases.
- 2026-09-23 — Cancelling a construction site loses its delivered materials. Why: there's no storage to refund into in milestone 0.
- 2026-09-23 — Maps are ASCII `rows` plus lists of buildings and free villagers (`MapDef`); the milestone-0 map lives in `sim/src/maps/` as a fixture, as the milestone prompt asks. Tuning numbers (tree logs etc.) still come from content. Why: readable in review, and the layout isn't balance data.
- 2026-09-23 — Save format = `JSON.stringify(state)` with a `version` field; loading any other version throws. Why: CLAUDE.md says a save is the serialized state; the version check makes future migrations explicit.
- 2026-09-23 — The PRNG (mulberry32) is in place and seeded, but no milestone-0 system draws from it. Why: nothing in milestone 0 needs randomness, and ties already break by ID.
- 2026-09-23 — Tick order: commands → movement → woodcutting → hauling → construction → `tick += 1`. Movement runs first so the other systems see this tick's arrivals. Why: one fixed, documented order (also in `step.ts`).
- 2026-09-23 — Movement follows tile centres; each segment is 1000 or 1414 units and position is interpolated with integer division. Leftover speed carries over into the next segment. Why: integer positions that never drift, with no `Math.sqrt`.
- 2026-09-23 — The woodcutter picks the nearest tree by octile distance from where it stands (ties by ID), skipping any it can't path to, and chops from a walkable neighbouring tile. When no tree is reachable or the buffer is full, it idles and retries every `idleRetryTicks`. Why: the spec says "nearest"; octile is cheap and matches movement cost; retrying avoids A* every tick.
- 2026-09-23 — A woodcutter arriving with a full buffer waits at the door holding its log until there's room. Why: the buffer capacity stays a hard limit for producers.
- 2026-09-23 — Hauling sits behind `LogisticsModel { init, update }`, chosen by `state.logistics.model` from a registry. `listSupplies`/`listDemands` are shared helpers. Why: the flag-relay prototype can plug in without touching other systems. Superseded by [ADR-0001](adr/0001-logistics-model.md): the interface is gone and job dispatch is called directly.
- 2026-09-23 — Job dispatch: each idle carrier (ID order) takes the oldest site with unmet need and the nearest source with unreserved stock, and only if the drop-off is reachable from the pickup. One job per carrier; the carrier waits a tick after finishing before taking the next. Reservations and incoming amounts are derived from the jobs list, not stored. Why: simple, fair (oldest first), and reservations can't drift out of sync.
- 2026-09-23 — If a site is cancelled mid-haul, the carrier stops at the next tile centre and then returns its load to the source, even past buffer capacity. An empty-handed carrier just drops the job. Why: no logs vanish from a carrier's hands; capacity limits producers, not returns.
- 2026-09-23 — Construction: the build timer only runs once every material is delivered; there's no builder villager in milestone 0. Why: the prompt says "all logs delivered and build time has passed"; builders are a later feature.
- 2026-09-23 — Hut test limit N = 3200 ticks (160 s at 1×). Measured: the hut at (4,16) completes at tick 2127, so N is about 1.5× that. Why: enough margin for small tuning changes while still failing on a real stall.
- 2026-09-23 — The main thread owns the game clock (Pixi ticker): real frame time × speed → whole ticks, sent to the worker as `advance {ticks, commands}` with at most one request in flight and at most 10 ticks per request. The worker only steps when asked. Why: matches CLAUDE.md ("the client decides how many ticks to run per frame"), and pause is simply "send nothing".
- 2026-09-23 — The worker returns a full-state snapshot plus the previous tick's villager positions; the renderer interpolates between them using the clock's leftover fraction. Why: exact interpolation even when several ticks run in one batch; full snapshots are small on a 24×24 map (diffs can come later).
- 2026-09-23 — Commands queue on the main thread and ride on the next `advance`. While paused, a placed hut appears when the game resumes. Why: keeps "commands are applied on a tick" strict, with no side channel into the sim.
- 2026-09-23 — Game speed (pause/1×/2×/3×) is UI state, not sim state, and isn't saved. Why: pausing mustn't change the simulation, and a loaded game starts at the speed the player already has.
- 2026-09-23 — Frame gaps longer than 250 ms are dropped, not caught up; a hidden browser tab therefore pauses the game (the browser stops animation frames). Why: no burst of hundreds of ticks when a tab comes back.
- 2026-09-23 — Save/load: one slot in `localStorage` (`candlemarch.save`); the main thread stores what the worker serializes. Why: the milestone asks only for browser storage; workers have no `localStorage`.
- 2026-09-23 — Rendering: TILE_W = 128 (2:1 tiles) in `iso.ts`; art heights scale from TILE_H. Depth sort by gx + gy of each object's front tile, villagers slightly in front at ties. Static objects redraw only when what they show changes. Why: one constant to change for 256×128 art later; cheap and correct enough for small footprints.
- 2026-09-23 — The HUD takes its colours from `palette.ts` through CSS variables. Why: one palette module for all placeholder art, as CLAUDE.md asks.
- 2026-09-23 — Extra input beyond the brief: Shift-click keeps placing; Esc/right-click cancels build mode; keys B (build hut), Space (pause), 1–3 (speed). No UI for `cancelConstruction` yet; the command exists and is tested. Why: cheap conveniences; a site-selection panel is a feature of its own.
- 2026-09-25 — Villager roles are renamed to Jobs everywhere (`content.jobs`, `JobId`, `VillagerComponent.job`, `employs[].job`), and `STATE_VERSION` goes to 2. Why: `CONTEXT.md` makes Job the only term; the component field rename breaks old saves.
- 2026-09-25 — Loading fills in state added after a save was made: `normalizeLoadedState` copies missing top-level fields and component stores from `createEmptyState`, and a field added inside an existing component gets one explicit line there. `STATE_VERSION` is bumped only for breaking changes (renames, removals, changed meanings), and a mismatch still refuses to load. Why: purely additive features keep old saves working without a migration.
- 2026-09-25 — In job dispatch, a carrier's delivery is a Haul: `Haul`, `state.logistics.hauls`. The model keeps the name "job dispatch". `STATE_VERSION` goes to 3. Why: "Job" now means only what a villager does (`CONTEXT.md`), and renaming a state field breaks old saves.
- 2026-09-25 — Roads are a sparse per-tile layer, `map.roads` (tile index → `RoadId`), not entities. Tiles without a road are absent. Why: a road belongs to its tile like terrain does, lookups are direct, and an empty `{}` default lets older saves load through `normalizeLoadedState` (which now fills missing `map` fields too) without a version bump.
- 2026-09-25 — `layPath`/`removePath` need both L ends on the map; otherwise they're ignored (which also keeps a stray huge coordinate from building a huge L). Laying reuses `blockedGrid` plus the terrain's `buildable` flag, so trees, footprints and unwalkable terrain reject the whole L; stockpile tiles will join the rule when stockpiles exist. Laying over an existing road sets it to dirt path. Why: one rule shared with the client preview (`canLayPath`), and the simplest all-or-nothing check.
- 2026-09-25 — Walking speed comes from the tile being walked onto: `walkSpeed × speedPercent / 100`, truncated. If a walker reaches a tile centre partway through a tick and the next tile has a different speed, the rest of that tick's movement is rescaled to the new speed. Why: matches the A* step cost (the tile being entered decides), and a fast road doesn't carry its speed onto grass.
- 2026-09-25 — Every walker's A* is road-aware, not only carriers': step cost = `trunc(length × 100 / speedPercent of the tile entered)`. The heuristic applies the same per-step truncation at the fastest speed in content (at least 100), so it never overestimates: truncating the whole octile distance at once could overestimate by up to 1 per step. `walkGrid()` builds the blocked and speed grids for both `walkTo` and job dispatch. Why: one movement rule for everyone. Because the heuristic is scaled even on maps without roads, equal-cost ties may resolve differently than in milestone 0, but they still resolve deterministically.
- 2026-09-25 — Buildings can't be placed with any footprint tile on a road; the door tile may be on one. Why: a road under a footprint would be unwalkable yet still linked to its neighbours, and doors on roads are how buildings join the network (they count as Flags in flag relay). (Flags: see [ADR-0001](adr/0001-logistics-model.md), flag relay removed.)
- 2026-09-25 — A Stockpile is an entity: its `tile` is the origin and `stockpile` holds `size` and `goods` (map tile index → `ResourceAmount`, empty tiles absent). `stockpileTileCapacity` sits in a new `content.logistics` section. No `STATE_VERSION` bump: the new store is filled in on load. Why: plain data with direct per-tile lookups, and the tile index order gives the "ties by tile index" rule for free.
- 2026-09-25 — A building's door can't be on a stockpile tile, just as a stockpile can't cover a door. Why: the same rule both ways; a door is where carriers queue, not storage.
- 2026-09-25 — Job dispatch picks the stockpile tile when it hands out a haul: pickup is the tile nearest the carrier holding unreserved goods; drop-off is the tile nearest the pickup with room once hauls already bound for it arrive (a tile another haul is bringing a different resource to has no room). They're stored as optional `fromTile`/`toTile` on the Haul, so saves with hauls in progress still load. Why: exact per-tile reservations keep the capacity and one-resource rules without re-choosing on arrival.
- 2026-09-25 — Goods being returned to a stockpile tile count against its room, so dispatch won't promise that room to a new drop-off. They still go back even if that overfills the tile (possible only when the drop-off was promised before the return began), as returns to a building buffer already do; if the tile holds another resource by then, they're lost. A carrier in the drop-off phase now finishes its haul when its source disappears (it used to stand still). Why: returns are rare and bounded by one load; removable stockpiles made the source-gone case reachable.
- 2026-09-25 — Staffing is derived, not stored: each tick after construction, every building's open positions (its `employs` minus villagers with that Workplace and Job) draft the lowest-ID idle Carrier, buildings in ID order. The logistics model decides idleness (`LogisticsModel.isIdle`; in job dispatch, no current haul). `openPositions()` is exported for the "no worker" icon. Why: no new state to save or keep in sync, and map workplaces start full so they're untouched.
- 2026-09-25 — Flag relay's state is its own `LogisticsState` variant (`model: 'flagRelay'`): placed Flags (tile indices), goods waiting per Flag, stored Segments and staffed carriers. A Flag's ID is its tile index; door Flags aren't stored but derived each tick from doors on roads. `placeFlag`/`removeFlag` are ignored under job dispatch, and a placed Flag is dropped when the path under it goes. Why: flags only mean something in model B, and tile indices give "ties by Flag ID" for free. Superseded by [ADR-0001](adr/0001-logistics-model.md).
- 2026-09-25 — Segments are derived every tick: from each Flag, a breadth-first walk over road tiles that stops at Flags finds its neighbours, and the shortest such road (ties by the fixed neighbour order) is the Segment. A junction without a Flag therefore gives one Segment per pair of Flags meeting there. Stored Segments keep their ID while their tiles are unchanged; any change replaces them with new IDs and releases their carriers. If the Segment's Flag or path was removed, the goods in its carrier's hands are lost; if it only changed because the road around it did (a Flag or door added in it, a road joined to it), the carrier puts its load on the Flag it was heading to, even past capacity. A door that lands next to a Flag can make a 1-step Segment; the 2-tile spacing only limits placed Flags. Why: the spec loses goods only on removal, and IDs from a counter (`nextSegmentId`) make "oldest Segment first" exact. Superseded by [ADR-0001](adr/0001-logistics-model.md).
- 2026-09-25 — Staffing: each unstaffed Segment, oldest first, takes the lowest-ID idle Carrier that can walk to it; it walks to the nearer end and waits there. Segments are staffed in the hauling step, before Workplaces draft, so under flag relay Segments get carriers first. Why: matches how Workplaces draft; the scenario maps' fixed carrier counts make the trade-off visible in the playtest. Superseded by [ADR-0001](adr/0001-logistics-model.md).
- 2026-09-25 — Relay routing: each good is bound to a destination (site or stockpile, and the Flag it's handed over at) when it enters the network, and hops along the shortest route by Segment length. At each Flag the next hop is recomputed: the neighbour minimising Segment length plus its route length, ties to the lowest Flag ID. Unstaffed Segments count as usable, so goods wait there rather than detour. Why: recomputing per hop copes with network changes without storing routes. Superseded by [ADR-0001](adr/0001-logistics-model.md).
- 2026-09-25 — Relay dispatch: every tick each demand (sites oldest first, then stockpiles, as in job dispatch) takes one unit at a time from the source nearest along the road, ties to the lower source Flag ID, then destination Flag ID, then source order. Sources are goods on Flags without a destination, building buffers (moved onto the door Flag at once) and stockpiles (a good is queued on the stockpile's Flag but stays on the stockpile until a carrier loads it). A source only sends onto a Flag with room. A demand's need is its missing amount minus every good already bound for it. Why: one unit per good matches the one-good-per-carrier relay, and counting bound goods keeps sites from being oversupplied. Superseded by [ADR-0001](adr/0001-logistics-model.md).
- 2026-09-25 — Relay reservations: goods queued from a stockpile count as reserved there until loaded. At a stockpile Flag the carrier picks the tile when it sets out: to load, the nearest tile holding the resource once other carriers walking to load there are counted; to unload, the nearest with room once other carriers walking to unload there are counted (none if one brings another resource). Ties go to the lowest tile index, distance is octile from the Flag. Only placed Flags serve stockpiles, not doors. Why: the same exact per-tile reservations as job dispatch, derived from carrier tasks rather than stored. Superseded by [ADR-0001](adr/0001-logistics-model.md).
- 2026-09-25 — Goods whose destination goes (site cancelled, stockpile removed, Flag gone or no longer connected) lose it and wait on their Flag, where dispatch can bind them to another demand; one in a carrier's hands is dropped on the next Flag first. A good queued from a stockpile just stays on the stockpile. If the unload tile has another resource when the carrier gets there, or the stockpile is gone, the good is lost. Goods nothing wants yet keep their place on the Flag and count against its capacity. Why: the relay equivalent of job dispatch's returns, without walking goods backwards. Superseded by [ADR-0001](adr/0001-logistics-model.md).
- 2026-09-25 — A relay carrier carries one good at a time, walks exactly along its Segment's road tiles (`walkAlong`), and uses A* only to reach its Segment and stockpile tiles. A carrier at a full Flag swaps its good for the oldest one there going back along its Segment; with none, it waits holding its good. An idle carrier walks to its Segment's other end for goods that go its way or are delivered there. Why: Settlers-style belts; one good per trip is what makes a Segment's throughput readable, and the swap keeps a carrier from waiting on a Flag only it can empty. Jams across several Segments are still possible and are left for the playtest to judge. Superseded by [ADR-0001](adr/0001-logistics-model.md).
- 2026-09-25 — Maps can start with paths and Flags, drawn in `rows` (`=` dirt path, `F` dirt path with a Flag), and with `sites` and `stockpiles` lists (both optional). Entities are created as trees, buildings with employees, sites, stockpiles, free villagers; Flags are placed last, in tile order, and only under flag relay (under job dispatch an `F` is plain path). Buildings, sites, stockpiles and Flags that couldn't be placed by the usual rules throw; path tiles aren't checked beyond their legend character, since buildings and stockpiles already refuse roads. Why: roads read best on the grid itself; rectangles and sites are clearer as coordinates; one map serves both models. The `F` character and Flags are gone since [ADR-0001](adr/0001-logistics-model.md).
- 2026-09-25 — `createInitialState(seed, map, content, model)` takes the logistics model, defaulting to job dispatch. `sim` exports a `maps` registry keyed by map name; the client's New game request sends a map name and model, and the worker looks the map up. Why: the worker builds state from plain data, and names are what the dev panel lists.
- 2026-09-25 — Scenario Carrier counts: short haul 2 (one Segment, so one Carrier idles under flag relay), long haul 3 and branching network 5 (one per Segment). Why: each model delivers from the same pool, and short haul shows job dispatch's parallel hauling against one relay Carrier. Flag relay is gone ([ADR-0001](adr/0001-logistics-model.md)); the counts stay.
- 2026-09-25 — Scenario test goal: at least 5 logs on the stockpile, and on branching network the site built too. Limits N (about 1.5× the slower model, seed 1): short haul 1300 (measured A 841, B 834), long haul 2300 (A 1270, B 1471), branching network 3000 (A 1339, site at 1186; B 1992, site at 1695). Why: 5 logs shows a steady flow rather than one delivery; the margin matches the milestone-0 hut test. The woodcutters (about 80 ticks per log) are the bottleneck, so these aren't a throughput comparison. Limits since [ADR-0001](adr/0001-logistics-model.md): see the 2026-09-26 line below.
- 2026-09-25 — The New game panel shows only in dev builds (`import.meta.env.DEV`); the HUD reads the running model from `state.logistics.model`, so a loaded save shows its own. The renderer's static views now include their tile in their redraw key. Why: the panel is a playtest tool; with several maps, an entity ID can come back at another tile after a new game or load. The model picker and HUD model readout are gone since [ADR-0001](adr/0001-logistics-model.md).
- 2026-09-25 — Tool shortcuts: B hut, W woodcutter's hut, R path, X remove path, F flag (click a path to place, click a Flag to remove), S stockpile, D demolish (Flag, stockpile or construction site). Drag tools take over left-drag; middle-drag still pans. Why: removal of Flags, stockpiles and sites needed a way in without adding a tool per command. The F tool is gone since [ADR-0001](adr/0001-logistics-model.md).
- 2026-09-26 — Goods for storage go to the nearest stockpile with room (straight-line from the pickup under job dispatch, along the road under flag relay), ties to the older one. Sites still come first, oldest first. Why: filling the oldest stockpile first carried goods past nearer ones, which read as a bug in play.
- 2026-09-26 — Job dispatch measures nearness by walking cost (roads included) from the carrier to the pickup and from the pickup to the drop-off, not straight-line distance. Why: flag relay already measures along the road; straight-line distance ignored roads and handicapped job dispatch in the playtest.
- 2026-09-26 — Stockpiles have a priority (high, normal, low; default normal) and a list of resources they refuse (default none). Higher priority is filled first whatever the distance; within one priority, the nearest wins. Refusing stops new deliveries but leaves goods where they are, and stockpiles still never feed each other. Set by selecting a stockpile with no tool active. Why: owner asked for it; moving goods between stockpiles is left out so goods can't bounce back and forth.
- 2026-09-26 — Logistics model picked: job dispatch ([ADR-0001](adr/0001-logistics-model.md)). Flag relay, the `LogisticsModel` interface and the model registry are deleted; `state.logistics` is now `{ hauls }` without a `model` tag, so `STATE_VERSION` goes to 4 and older saves (flag relay's included) no longer load. The New game panel picks only the map. Why: one model left, so the seam no longer earns its keep; dropping the tag and relay state is a breaking change.
- 2026-09-26 — Scenario tick limits are 1.5× job dispatch's measured times: short haul 1300 (841), long haul 1900 (1270), branching network 2000 (1339). Why: with flag relay gone, the slower model no longer sets them.
- 2026-09-26 — Biome force-ignores `.claude/` (`!!**/.claude`). Why: agent worktrees under `.claude/worktrees/` carry their own root `biome.json`, which made `pnpm lint` fail.
- 2026-09-26 — The hero is its own component (`hero: { type }`) with the shared `position` and `path` stores, not a villager, so no Job system ever sees it. Maps place it with an optional `hero: {x, y}`, spawned after free villagers; its type is the one placeholder hero until heroes are picked at game start. The new store is filled in on load, so no `STATE_VERSION` bump. Why: the spec says the hero isn't a villager, and walking reuses movement as is.
- 2026-09-26 — Placeholder hero walk speed 100 milli-tiles per tick (2 tiles/s, villagers 1.5). Why: a hero that kickstarts the village should outpace it a little; the playtest tunes it.
- 2026-09-26 — `orderHero` holds one order at a time. A new order replaces the old one at once, but a hero mid-step first finishes that step (`rerouteTo`), so it never jumps back to the last tile centre. An order to a tile it can't reach (blocked, off the map, walled in) is ignored and the old order stands, like other invalid commands. Why: RTS feel without snapping, and no pending-order state to save.
- 2026-09-26 — Client: with no tool, left-click on the hero selects it and left-click elsewhere deselects it (selecting a stockpile there, if any); right-click orders a move while it's selected. Esc and picking a tool clear the selection, and a tool takes clicks first. The hit test is the hero's drawn bounds plus 10 px, so the small figure is easy to click when zoomed out. Why: standard RTS control; selection is UI state and isn't saved.
- 2026-09-26 — Hero aura stub: content `aura: { radiusTiles: 5, speedPercent: 125 }`. A building is boosted when it's a Workplace (it employs someone) and a footprint tile lies in a circle around the hero's tile (dx² + dy² ≤ r², whole tiles). Nothing is stored: `workSpeedPercent`/`boostedWorkplaces` derive it from positions. Why: a circle matches what the client draws; derived state can't drift and costs nothing in saves.
- 2026-09-26 — The aura scales a piece of work when it starts: a chop takes `max(1, trunc(gatherTicks × 100 / speedPercent))` (40 → 32 ticks), judged by the hero's position at that moment. Production systems will call the same `workTicks`. Why: the simplest integer rule; with a whole chop at 1–2 s, the delay before the boost shows is too short to matter in a stub.
- 2026-09-26 — Every map starts its hero out of aura range of any Workplace (a test checks it). Why: the scenario and milestone timings stay as measured without the hero, and the logistics playtest isn't skewed; the player walks the hero over to get the boost.
- 2026-09-26 — Client: boosted Workplaces always get a gold ground mark; the aura radius shows only while the hero is selected, centred on the hero's tile (as the sim measures it), so it moves a tile at a time. Why: the player should see a boost is on without selecting anything, and the radius matches the rule exactly.
- 2026-09-26 — Hero hand-carry under job dispatch: the hero walks anywhere, as Carriers do (with flag relay gone, the off-road question is moot). Orders: `gather {tree}`, `deliver {target}` (a site or stockpile), `pickup {source}` (a building's output buffer or a stockpile), plus `move`. Each replaces the current order; one that can't be carried out now is ignored. The order and the goods in hand live on the hero component (`order`, `carrying`). Why: explicit, checkable commands; the order is plain data, so a save mid-order resumes exactly.
- 2026-09-26 — Placeholder hero carries 5 (villagers 1). Gathering follows the woodcutter's rules (40 ticks per chop, 1 log each) but keeps chopping the same tree until it's gone or the hero's hands are full; it doesn't move on to another tree. Why: meaningful by-hand hauling early on (a hut is 10 logs), and the player picks each tree.
- 2026-09-26 — A hero ordered to deliver to a site promises `min(in hand, still missing − carriers' incoming)`, and dispatch counts that promise as incoming from the moment of the order until it's delivered or the order is replaced (owner's call). An order the site doesn't need after carriers' hauls is refused. On arrival the hero hands over exactly the promised amount and keeps the rest. Why: carriers never double-deliver, and the promise can't go stale while the hero walks.
- 2026-09-26 — Stockpile deliveries and all pickups reserve nothing. Delivering fills the stockpile tile nearest the hero with room once carriers' promised drop-offs are counted, then walks to the next such tile until its hands are empty or the pile is full. A pickup takes only goods no Carrier has claimed (buffer or tile), and tops up what the hero already holds of the same resource. Why: carriers' reservations stay exact without new bookkeeping; the hero adapts on arrival instead.
- 2026-09-26 — The sim decides what a right-click means (`heroOrderAt`): tree → gather; building, site or stockpile → deliver if it wants what the hero holds, else pickup if it has goods to take, else nothing (the HUD says so); open ground → move. The tick order gains a hero step right after movement. Why: CLAUDE.md keeps game rules out of the client, and the command is still checked when applied.
